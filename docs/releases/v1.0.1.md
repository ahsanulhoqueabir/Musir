## Summary

Musir 1.0.1 is the first public release of **Musir**, a minimal, fast local music player for
Android built with Flutter. Everything stays on the device: no accounts, no ads, no analytics
and no network access.

This release ships the full feature set — library scanning, browse, search, a now-playing
screen with a reorderable queue, playlists, favorites and history — together with a
refreshed brand identity, a branded splash and adaptive launcher icon, and a set of layout
and correctness fixes.

---

## Key features

### Library

- Scans device storage in a **background isolate**, so the UI never blocks on a large library.
- Reads tags and embedded artwork with a pure-Dart scanner (`audio_metadata_reader`).
- Tolerates missing metadata: files with unreadable tags still appear, titled from the filename.
- Hides duplicate files and rescans **incrementally**, so only new or changed files are re-read.
- Folders containing `.nomedia`, hidden folders, `Android/`, and
  Ringtones/Notifications/Alarms are skipped on purpose.

### Browse

Four library tabs — **Songs**, **Albums**, **Artists** and **Favorites** — plus
**Recently played** and **Recently added** on the home screen.

- Songs are sortable, with a configurable default sort order.
- Album and artist detail screens link back to their tracks.
- Favorites are persisted locally and reachable from their own tab.

### Search

- Debounced search across **title, artist and album**.
- Results are ranked, with dedicated sections for matching tracks, albums and artists.

### Now Playing

- Large artwork, seek bar, and previous / play / next transport controls.
- **Shuffle** physically reorders the queue (current track first) rather than relying on the
  engine's hidden shuffle order, so the queue you see and reorder is the real play order.
  Turning shuffle off restores the original order.
- **Repeat** with off / all / one modes.
- **±10 s skip** buttons.
- Favorite toggle directly on the player.
- **Queue sheet**: tap to jump, drag to reorder, swipe to remove.
- Play next / add to queue via the track action menu, plus album and artist links.

### Background playback

- Media notification and **lock-screen controls**.
- **Headset and Bluetooth buttons** handled through `just_audio_background`.
- Audio focus handling: playback pauses for calls and other audio apps, and resumes where the
  other app releases focus.

### Playlists

- Create, rename, and delete with an **Undo** action.
- Add and remove tracks, drag to reorder, and play a playlist straight away.
- **Collage artwork**, song count and total duration per playlist.

### Favorites and history

- Persisted locally in **SQLite via Drift**.
- The last queue and playback position are **restored on launch** (optional, configurable).

### Settings

Theme (system / light / dark) · default sort order · rescan library · resume last queue ·
skip silence · privacy notice · app version and open-source licenses.

## Bug fixes

- **Albums are no longer split by guest artists.** Albums are grouped by the *album artist*
  tag, falling back to the containing folder when that tag is absent. Previously, grouping by
  the track artist split a single album in two as soon as one track featured a guest artist.
  Fallback-by-folder also keeps separate "Greatest Hits" folders apart.
- **The privacy dialog no longer crashes.** Closing it now uses its own context; using the
  screen's context popped the page route and crashed `go_router`.

## Technical improvements

### Release automation

`tool/release.sh` automates a release end to end:

- bumps the version in `pubspec.yaml` (`patch` / `minor` / `major` / `build` / `none`),
- builds the universal and split-per-ABI release APKs,
- collects them under `dist/<version>+<build>/`,
- validates the **version name**, **version code** (including Flutter's per-ABI offsets) and
  **native libraries** of every APK using `aapt`.

A failed run restores `pubspec.yaml`, so a broken build never consumes a version.

### Continuous integration

`.github/workflows/ci.yml` runs on GitHub Actions: `dart format` check, `flutter analyze`
(must report zero issues), the full test suite, and both debug and release APK builds,
uploading the APKs as a build artifact.

### Build configuration

- `compileSdk` raised to **37**, as required by `permission_handler_android`.
- Kotlin incremental compilation disabled — it fails when the pub cache and the project live
  on different Windows drives.
- `dist/` and release backup files are git-ignored.

### Testing

**120 tests** run in CI, covering:

- repositories against in-memory SQLite (cascades, rescans, ordering),
- sort / search / dedupe / grouping logic,
- the scanner on generated audio files (tags, artwork, `.nomedia`, corrupt files),
- `PlaybackController` — queue edits, shuffle / repeat, completion, errors, missing files and
  persistence / restore — against a fake engine,
- widget tests that boot the real app with fakes and drive the permission, scan, playback,
  player, favorites, queue, search, playlist, settings and restore flows, plus a **layout
  stress matrix** (320 dp phone, 1.8× text, tablet; light and dark; very long metadata) that
  fails on any overflow.

```bash

```

want to publish checksums as well.

## Installation

1. Download the APK that matches your device (see the table above).
2. Allow installation from your browser: Android will ask you to permit
   **Install unknown apps** for the app you downloaded the file with.
   Alternatively, transfer the APK to the device and open it with your file manager.
3. On first launch, grant the **audio permission** so Musir can read your music. If you dismiss
   it twice, Android stops prompting — use **Settings → Apps → Musir → Permissions** and enable
   *Music and audio*, or use the **Open settings** button on Musir's permission screen.
4. The library scan starts automatically. You can trigger it again from
   **Library → Rescan** or **Settings → Rescan library**.

## Compatibility notes

### Requirements

- **Android 7.0 (API 24) or newer** (`minSdk` 24).
- Built and targeted against **compileSdk / targetSdk 36–37**.

### Permissions requested

| Permission | Why |
|---|---|
| `READ_MEDIA_AUDIO` (Android 13+) | Read audio files to build the library |
| `READ_EXTERNAL_STORAGE` (Android 12 and below, `maxSdkVersion=32`) | Read audio files to build the library |
| `FOREGROUND_SERVICE` | Keep playing with the screen off |
| `FOREGROUND_SERVICE_MEDIA_PLAYBACK` | Keep playing with the screen off |
| `WAKE_LOCK` | Keep playing with the screen off |
| `ACCESS_NETWORK_STATE` | Reported by a plugin dependency; Musir itself makes no network requests |

Release builds request **no `INTERNET` permission** — the debug and profile manifests add it
for Flutter tooling only.

### Supported audio formats

The scanner looks for `.mp3`, `.m4a`, `.aac`, `.flac`, `.wav`, `.ogg`, `.opus`, `.oga`, `.wma`,
`.m4b`, `.amr`, `.3gp` and `.mka`. Whether a file actually *plays* depends on the device's
codecs (ExoPlayer). Files whose tags cannot be read still appear, titled from the filename,
and files that fail to decode are skipped with a message.

### Signing

These APKs are signed with the **Android debug certificate**, because no production keystore
was configured for this build (`android/key.properties` is git-ignored and not present).
Android will therefore show an *"unknown source"* warning on install — allow it via
**Settings → Apps → Special app access → Install unknown apps**.

To produce a properly signed release, provide `android/key.properties` (see
`android/key.properties.example`) and rebuild. Debug-signed builds are not suitable for
Play Store distribution.

### Known limitations

- Tag parsing was verified against generated MP3 and WAV files only. M4A, FLAC, OGG and Opus
  rely on `audio_metadata_reader` and have not been exercised against real-world files.
- The queue bottom sheet and other overlays are covered by widget tests but are not visible
  in the screenshots above.
- Some vendors aggressively kill foreground services. If playback stops in the background,
  disable battery optimization for Musir.
